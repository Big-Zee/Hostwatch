# Proposal

## Why

The owner wants to know when their Ubuntu PC is switched on and who logs into it, without checking the machine. Posting to a Slack channel through an incoming webhook sends the alert to their phone right away. HostWatch has no code yet, so this change sets up the shared base (config, Slack delivery, install) that the planned uptime, top-processes and shutdown reports will build on.

## What Changes

- New stdlib-only Python 3 service `slack-heartbeat` installed system-wide on Ubuntu 24.04.
- **Boot notification**: after boot, once the network is up, post one Slack message with:
  - date and time with timezone
  - hostname
  - local IPs of active, non-virtual interfaces
  - public IP, which is optional and best-effort
- **Login notification**: post one Slack message per login with username, login type (graphical, TTY or SSH), date/time, hostname, and remote IP for SSH. Logins come from PAM `pam_exec`, chosen over a systemd user unit (reasoning in design.md).
- **Configuration** in `/etc/slack-heartbeat/config.ini` (root-only, mode 600): webhook URL, public IP on/off, timezone display. `config.example.ini` is committed and holds only a placeholder webhook.
- **Reliable delivery**: Slack Block Kit messages with a plain-text fallback that read well on mobile. Retries with backoff. Failures go to the systemd journal. Boot and login are never delayed or broken.
- **Install / uninstall scripts**: install copies files, creates the config from the example and enables the boot unit and PAM hook. Uninstall reverses all of this.
- A `test` command that sends a sample message, and a dry-run mode that prints the payload without sending it.

Out of scope (later changes): hourly uptime report, hourly top processes, shutdown notification.

## Capabilities

### New Capabilities
- `heartbeat-config`: Where the service reads its settings, which settings exist, their defaults and validation, and how the file is protected.
- `slack-delivery`: How messages reach Slack: webhook posting, message layout and mobile fallback, retry/backoff, journal logging, and keeping the webhook secret.
- `boot-notification`: Announcing that the host has booted, with time, hostname, local and public addresses, without affecting boot.
- `login-notification`: Announcing interactive user logins (graphical, TTY, SSH) exactly once per session, without affecting login.
- `service-installation`: Installing, configuring and cleanly removing the service on Ubuntu.

### Modified Capabilities
None. No specs exist yet.

## Impact

- **New code**: Python package under `src/slack_heartbeat/`, CLI wrapper `bin/slack-heartbeat`, systemd unit, pam-auth-update profile, `config.example.ini`, `install.sh`, `uninstall.sh`, unit tests and README.
- **Host changes when installed**:
  - files under `/usr/local/lib/slack-heartbeat/`, `/usr/local/bin/`, `/etc/systemd/system/`, `/usr/share/pam-configs/` and `/etc/slack-heartbeat/`
  - `/etc/pam.d/common-session` regenerated by `pam-auth-update`
- **External services**: Slack incoming webhook. Optionally a public-IP lookup service (default `https://api.ipify.org`).
- **Dependencies**: none beyond Python 3 (stdlib), systemd, iproute2 and PAM, all present on stock Ubuntu 24.04.
- **Security**: the webhook URL is a secret. It lives only in the root-only config file. The repo already ignores `config.ini` and `.env`.
